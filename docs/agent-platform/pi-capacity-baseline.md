# Pi 容量基线

本文件只规定容量对比怎么成立。它不记录吞吐、p50、p95、错误率、内存或 CPU 的测量值，也不宣布容量达标。

## 可比对的两侧

对比必须来自**同一种部署形态**的两侧：

1. 该形态的上一发布版本。
2. 本分支。本分支以 Pi 为唯一 Agent 引擎，没有进程内 Legacy Agent 回退。`packages/api/src/agents/runtime/dispatcher.spec.ts` 会拒绝 `engine: legacy`。容量对比沿用这个事实，不恢复 Legacy。

同一种部署形态指拓扑、副本数、数据服务、入口和资源规格都相同。上一发布版本与本分支各跑一次相同的受支持 Agent 工作负载，各自留下一份结果 JSON。换了部署形态的结果不能充当基线。

本变更不附带结果文件，也不附带负载采集器。数字只能源自上述两侧的真实采集。估算、单测耗时和其他部署形态的读数都不能填进结果文件。

## 指标

每份结果只使用下面这些指标。延迟要同时给出 p50 和 p95。

| 字段 | 含义 |
| --- | --- |
| `deploymentForm` | 部署形态标识。两侧必须相同 |
| `revision` | 上一发布版本标识，或本分支的发布/提交标识 |
| `throughput` | 吞吐 |
| `p50` | 延迟 p50 |
| `p95` | 延迟 p95 |
| `errorRate` | 错误率 |
| `memory` | 内存 |
| `cpu` | CPU |
| `samples` | 非空样本数组。每个样本重复上述六个数字字段 |

单位和采集窗口以该次部署的测量记录为准。本框架不另定绝对值门槛。

`scripts/pi-capacity/compare.mjs` 只读取这两份 JSON。它不访问服务，也不从样本重新计算汇总字段；表中的六个指标就是结果文件里写明的汇总值。样本数组用来确认这次结果背后有采集记录。

## 未测量

出现下面任一情况时，还没有可引用的容量结论，结论只能是**未测量**：

- 缺少上一发布版本或本分支的结果文件
- 部署形态不一致，或任一必填字段缺失、不是有限数字
- `samples` 缺失、不是数组，或样本为空

此时比较脚本以非 0 状态退出，并打印 `未测量`。

两侧字段齐全且部署形态一致时，脚本只打印对比表。对比表不是容量结论，脚本不输出「容量达标」。是否接受这组差异，由下面的签字决定；签字前不得把对比表写成达标。
